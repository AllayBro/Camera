### 1. XML-схемы (пункты 2, 3.3 задания)

#### 1.1. Схема типов данных веб-сервиса

**Файл:** `src/main/resources/wsdl/drone_service.xsd`

**Назначение:** Определяет структуру данных для операций веб-сервиса и обработки ошибок.

**Target Namespace:** `http://www.example.com/drone/service`

**Содержит:**

1. **Элементы запросов (Request Elements):**
   - `GetDroneInfoRequest` - запрос информации о дроне
     ```xml
     <xs:element name="GetDroneInfoRequest">
         <xs:complexType>
             <xs:sequence>
                 <xs:element name="droneId" type="xs:string"/>
             </xs:sequence>
         </xs:complexType>
     </xs:element>
     ```
   - `RegisterFineRequest` - запрос регистрации штрафа
     ```xml
     <xs:element name="RegisterFineRequest">
         <xs:complexType>
             <xs:sequence>
                 <xs:element name="droneId" type="xs:string"/>
                 <xs:element name="violation" type="xs:string"/>
                 <xs:element name="penalty" type="xs:double"/>
             </xs:sequence>
         </xs:complexType>
     </xs:element>
     ```
   - `GetFinesRequest` - запрос списка штрафов
     ```xml
     <xs:element name="GetFinesRequest">
         <xs:complexType>
             <xs:sequence>
                 <xs:element name="droneId" type="xs:string"/>
             </xs:sequence>
         </xs:complexType>
     </xs:element>
     ```

2. **Элементы ответов (Response Elements):**
   - `GetDroneInfoResponse` - ответ с информацией о дроне
   - `RegisterFineResponse` - ответ о результате регистрации штрафа
   - `GetFinesResponse` - ответ со списком штрафов

3. **Fault элементы (для обработки ошибок):**
   - `InvalidDroneIdFault` - ошибка неверного ID дрона
     ```xml
     <xs:element name="InvalidDroneIdFault">
         <xs:complexType>
             <xs:sequence>
                 <xs:element name="message" type="xs:string"/>
                 <xs:element name="droneId" type="xs:string"/>
             </xs:sequence>
         </xs:complexType>
     </xs:element>
     ```
   - `ValidationFault` - ошибка валидации данных
   - `ServiceUnavailableFault` - ошибка недоступности сервиса

#### 1.2. Схема типов данных дронов

### 2. Абстрактное WSDL-описание (пункты 3, 4 задания)

**Файл:** `src/main/resources/wsdl/DroneServiceAbstract.wsdl`

**Назначение:** Определяет абстрактное описание веб-сервиса без привязки к конкретному протоколу.

**Target Namespace:** `http://www.example.com/drone/service`

**Структура WSDL:**

#### 2.1. Элемент `<definitions>`

```xml
<definitions xmlns="http://schemas.xmlsoap.org/wsdl/"
             xmlns:tns="http://www.example.com/drone/service"
             xmlns:xsd="http://www.w3.org/2001/XMLSchema"
             xmlns:drone="http://www.example.com/drone"
             targetNamespace="http://www.example.com/drone/service"
             name="DroneServiceAbstract">
```

**Объяснение:**
- `targetNamespace` - пространство имен для элементов, определенных в этом WSDL
- `name` - имя WSDL документа
- Префиксы `tns`, `xsd`, `drone` - используются для ссылок на пространства имен

#### 2.2. Раздел `<types>`

Импортирует XML-схемы для определения типов данных:

```xml
<types>
    <xsd:schema targetNamespace="http://www.example.com/drone/service">
        <xsd:import namespace="http://www.example.com/drone"
                   schemaLocation="drone_target.xsd"/>
        <xsd:include schemaLocation="drone_service.xsd"/>
    </xsd:schema>
</types>
```

**Объяснение:**
- `<xsd:import>` - импортирует схему из другого namespace (`drone_target.xsd`)
- `<xsd:include>` - включает схему из того же namespace (`drone_service.xsd`)

#### 2.3. Раздел `<message>`

Определяет сообщения, которые передаются между клиентом и сервером:

**Сообщения запросов:**
- `GetDroneInfoRequestMessage` - запрос информации о дроне
- `RegisterFineRequestMessage` - запрос регистрации штрафа
- `GetFinesRequestMessage` - запрос списка штрафов

**Сообщения ответов:**
- `GetDroneInfoResponseMessage` - ответ с информацией о дроне
- `RegisterFineResponseMessage` - ответ о результате регистрации
- `GetFinesResponseMessage` - ответ со списком штрафов

**Fault сообщения:**
- `InvalidDroneIdFaultMessage` - сообщение об ошибке неверного ID
- `ValidationFaultMessage` - сообщение об ошибке валидации
- `ServiceUnavailableFaultMessage` - сообщение о недоступности сервиса

**Пример определения сообщения:**
```xml
<message name="GetDroneInfoRequestMessage">
    <part name="parameters" element="tns:GetDroneInfoRequest"/>
</message>
```

**Объяснение:**
- Документо-ориентированный стиль (единственная часть с глобальным элементом)
- `part name="parameters"` - имя части сообщения
- `element="tns:GetDroneInfoRequest"` - ссылка на глобальный элемент из XML-схемы

#### 2.4. Раздел `<portType>`

Определяет абстрактный интерфейс веб-сервиса с операциями:

```xml
<portType name="DroneServicePortType">
    <operation name="GetDroneInfo">
        <input message="tns:GetDroneInfoRequestMessage"/>
        <output message="tns:GetDroneInfoResponseMessage"/>
        <fault name="InvalidDroneIdFault" message="tns:InvalidDroneIdFaultMessage"/>
        <fault name="ServiceUnavailableFault" message="tns:ServiceUnavailableFaultMessage"/>
    </operation>
    
    <operation name="RegisterFine">
        <input message="tns:RegisterFineRequestMessage"/>
        <output message="tns:RegisterFineResponseMessage"/>
        <fault name="ValidationFault" message="tns:ValidationFaultMessage"/>
        <fault name="ServiceUnavailableFault" message="tns:ServiceUnavailableFaultMessage"/>
    </operation>
    
    <operation name="GetFines">
        <input message="tns:GetFinesRequestMessage"/>
        <output message="tns:GetFinesResponseMessage"/>
        <fault name="InvalidDroneIdFault" message="tns:InvalidDroneIdFaultMessage"/>
        <fault name="ServiceUnavailableFault" message="tns:ServiceUnavailableFaultMessage"/>
    </operation>
</portType>
```

**Объяснение:**
- `portType` - абстрактное определение интерфейса (без привязки к протоколу)
- Каждая операция имеет:
  - `input` - входящее сообщение (запрос)
  - `output` - исходящее сообщение (ответ)
  - `fault` - возможные ошибки (может быть несколько)

#### 2.5. Partner Link Type (пункт 3.7 задания)

```xml
<plnk:partnerLinkType name="DroneServiceLT" 
                      xmlns:plnk="http://schemas.xmlsoap.org/ws/2003/05/partner-link/">
    <plnk:role name="DroneServiceRole">
        <plnk:portType name="tns:DroneServicePortType"/>
    </plnk:role>
</plnk:partnerLinkType>
```

**Назначение:** Определяет тип связи для использования веб-сервиса в BPEL-процессах.

**Объяснение:**
- `partnerLinkType` - определяет роли партнеров при взаимодействии
- `role` - роль веб-сервиса (в данном случае - поставщик услуг)
- `portType` - ссылка на тип порта, через который происходит взаимодействие

### 3. Конкретное WSDL-описание (пункт 5 задания)

**Файл:** `src/main/resources/wsdl/DroneServiceConcrete.wsdl`

**Назначение:** Добавляет к абстрактному WSDL конкретную привязку к протоколу SOAP и определяет endpoint.

#### 3.1. Импорт абстрактного WSDL

```xml
<import namespace="http://www.example.com/drone/service" 
        location="DroneServiceAbstract.wsdl"/>
```

**Объяснение:** Импортирует абстрактное описание, чтобы использовать определенные там типы, сообщения и portType.

#### 3.2. SOAP привязка (Binding)

```xml
<binding name="DroneServiceBinding" type="tns:DroneServicePortType">
    <soap:binding style="document" 
                  transport="http://schemas.xmlsoap.org/soap/http"/>
```

**Параметры привязки:**
- `style="document"` - документо-ориентированный стиль (XML документы передаются как есть)
- `transport="http://schemas.xmlsoap.org/soap/http"` - протокол HTTP для передачи SOAP

**Привязка операции:**
```xml
<operation name="GetDroneInfo">
    <soap:operation soapAction="http://www.example.com/drone/service/GetDroneInfo"/>
    <input>
        <soap:body use="literal"/>
    </input>
    <output>
        <soap:body use="literal"/>
    </output>
    <fault name="InvalidDroneIdFault">
        <soap:fault name="InvalidDroneIdFault" use="literal"/>
    </fault>
</operation>
```

**Объяснение:**
- `soapAction` - идентификатор операции в HTTP заголовке SOAPAction
- `use="literal"` - литеральный стиль (XML из схемы используется напрямую, без обертки)
- `soap:fault` - привязка ошибки к SOAP

#### 3.3. Определение сервиса (Service)

```xml
<service name="DroneService">
    <port name="DroneServicePort" binding="tns:DroneServiceBinding">
        <soap:address location="http://localhost:8090/camera2/DroneService"/>
    </port>
</service>
```

**Объяснение:**
- `service` - определяет веб-сервис как точку доступа
- `port` - конкретная реализация порта с привязкой
- `soap:address` - физический адрес (URL) веб-сервиса

### 4. EJB-компонент (Stateless Session Bean) (пункт 6 задания)

**Файл:** `src/main/java/org/example/camera/soap/DroneServiceBean.java`

**Назначение:** Реализация веб-сервиса в виде сессионного компонента без состояния.

#### 4.1. Аннотации класса

```java
@Stateless
@WebService(
    name = "DroneServicePortType",
    targetNamespace = "http://www.example.com/drone/service",
    serviceName = "DroneService",
    portName = "DroneServicePort",
    wsdlLocation = "wsdl/DroneServiceConcrete.wsdl"
)
@SOAPBinding(style = SOAPBinding.Style.DOCUMENT, 
             use = SOAPBinding.Use.LITERAL, 
             parameterStyle = SOAPBinding.ParameterStyle.BARE)
@BindingType(value = jakarta.xml.ws.soap.SOAPBinding.SOAP11HTTP_BINDING)
public class DroneServiceBean {
```

**Объяснение аннотаций:**

1. **`@Stateless`** - сессионный компонент без состояния
   - Каждый вызов метода независим
   - Не хранит состояние между вызовами
   - Может обрабатывать множество клиентов одновременно

2. **`@WebService`** - превращает класс в веб-сервис
   - `name` - имя portType в WSDL
   - `targetNamespace` - пространство имен веб-сервиса
   - `serviceName` - имя сервиса
   - `portName` - имя порта
   - `wsdlLocation` - путь к WSDL файлу

3. **`@SOAPBinding`** - определяет стиль SOAP-привязки
   - `style = DOCUMENT` - документо-ориентированный стиль
   - `use = LITERAL` - литеральный стиль
   - `parameterStyle = BARE` - параметры без обертки

4. **`@BindingType`** - тип привязки протокола
   - `SOAP11HTTP_BINDING` - SOAP 1.1 через HTTP

#### 4.2. Реализация операции GetDroneInfo

```java
@WebMethod(operationName = "GetDroneInfo")
@WebResult(name = "GetDroneInfoResponse", targetNamespace = NAMESPACE)
public GetDroneInfoResponse getDroneInfo(
        @WebParam(name = "GetDroneInfoRequest", targetNamespace = NAMESPACE) 
        GetDroneInfoRequest request)
        throws InvalidDroneIdFaultException, ServiceUnavailableFaultException {
    
    String id = request.getDroneId();
    
    // Валидация
    if (id == null || id.isBlank()) {
        InvalidDroneIdFault fault = new InvalidDroneIdFault();
        fault.setMessage("ID дрона не может быть пустым");
        fault.setDroneId(id);
        throw new InvalidDroneIdFaultException("ID дрона не может быть пустым", fault);
    }
    
    // Бизнес-логика
    String result = switch (id) {
        case "d1" -> "DJI Mavic — активен";
        case "d2" -> "DJI Phantom — неактивен";
        default -> {
            InvalidDroneIdFault fault = new InvalidDroneIdFault();
            fault.setMessage("Дрон с ID " + id + " не найден");
            fault.setDroneId(id);
            throw new InvalidDroneIdFaultException("Дрон с ID " + id + " не найден", fault);
        }
    };
    
    // Формирование ответа
    GetDroneInfoResponse response = new GetDroneInfoResponse();
    response.setDroneInfo(result);
    return response;
}
```

**Объяснение:**
- `@WebMethod(operationName = "GetDroneInfo")` - имя операции в WSDL
- `@WebResult` - определяет имя элемента ответа
- `@WebParam` - определяет имя параметра в WSDL
- Метод возвращает объект ответа или выбрасывает Fault-исключение

#### 4.3. Реализация операции RegisterFine

```java
@WebMethod(operationName = "RegisterFine")
@WebResult(name = "RegisterFineResponse", targetNamespace = NAMESPACE)
public RegisterFineResponse registerFine(
        @WebParam(name = "RegisterFineRequest", targetNamespace = NAMESPACE) 
        RegisterFineRequest request)
        throws ValidationFaultException, ServiceUnavailableFaultException {
    
    String id = request.getDroneId();
    String violation = request.getViolation();
    double penalty = request.getPenalty();
    
    // Валидация всех полей
    if (id == null || id.isBlank()) {
        ValidationFault fault = new ValidationFault();
        fault.setMessage("ID дрона не может быть пустым");
        fault.setField("droneId");
        throw new ValidationFaultException("ID дрона не может быть пустым", fault);
    }
    if (violation == null || violation.isBlank()) {
        ValidationFault fault = new ValidationFault();
        fault.setMessage("Описание нарушения не может быть пустым");
        fault.setField("violation");
        throw new ValidationFaultException("Описание нарушения не может быть пустым", fault);
    }
    if (penalty < 0) {
        ValidationFault fault = new ValidationFault();
        fault.setMessage("Размер штрафа не может быть отрицательным");
        fault.setField("penalty");
        throw new ValidationFaultException("Размер штрафа не может быть отрицательным", fault);
    }
    
    // Сохранение данных (в памяти)
    FINES.computeIfAbsent(id, k -> new ArrayList<>())
            .add(violation + " (" + penalty + " руб.)");
    
    RegisterFineResponse response = new RegisterFineResponse();
    response.setResult("Штраф зарегистрирован для " + id);
    return response;
}
```

```java
private static final String WSDL_URL = "http://localhost:8090/camera2/DroneService?wsdl";
```

   ```java
   @WebService(name = "DroneServicePortType", ...)
   ```

### 7. Конфигурация

#### 7.1. Конфигурация Spring Boot

**Файл:** `src/main/resources/application.properties`
```
server.servlet.context-path=/camera2
server.port=8090
```

**Объяснение:**
- `server.port` - порт, на котором запускается сервер
- `server.servlet.context-path` - контекстный путь приложения

#### 7.2. Конфигурация JAX-WS для Spring Boot

**Файл:** `src/main/java/org/example/camera/config/JaxWsConfig.java`

```java
@Configuration
public class JaxWsConfig {
    
    @Bean
    public ServletListenerRegistrationBean<WSServletContextListener> wsServletContextListener() {
        return new ServletListenerRegistrationBean<>(new WSServletContextListener());
    }
    
    @Bean
    public ServletRegistrationBean<WSServlet> wsServlet() {
        ServletRegistrationBean<WSServlet> registration = 
            new ServletRegistrationBean<>(new WSServlet(), "/DroneService");
        registration.setLoadOnStartup(2);
        registration.setName("JAXWSServlet");
        return registration;
    }
}
```

**Объяснение:**
- Регистрирует JAX-WS сервлет в Spring Boot
- Указывает URL паттерн `/DroneService`

#### 7.3. Конфигурация веб-приложения

**Файл:** `src/main/webapp/WEB-INF/web.xml`

```xml
<!-- JAX-WS (Metro) -->
<listener>
    <listener-class>com.sun.xml.ws.transport.http.servlet.WSServletContextListener</listener-class>
</listener>

<servlet>
    <servlet-name>JAXWSServlet</servlet-name>
    <servlet-class>com.sun.xml.ws.transport.http.servlet.WSServlet</servlet-class>
    <load-on-startup>2</load-on-startup>
</servlet>

<servlet-mapping>
    <servlet-name>JAXWSServlet</servlet-name>
    <url-pattern>/DroneService</url-pattern>
</servlet-mapping>
```

#### 7.4. Конфигурация JAX-WS endpoints

**Файл:** `src/main/webapp/WEB-INF/sun-jaxws.xml`

```xml
<endpoints xmlns="http://java.sun.com/xml/ns/jax-ws/ri/runtime" version="2.0">
    <endpoint
        name="DroneServicePort"
        implementation="org.example.camera.soap.DroneServiceBean"
        url-pattern="/DroneService"/>
</endpoints>
```

**Объяснение:**
- Связывает URL паттерн с реализацией веб-сервиса
- `implementation` - класс EJB-компонента

## Примеры SOAP-сообщений

```xml
<?xml version="1.0" encoding="UTF-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
    <soap:Body>
        <GetDroneInfoRequest xmlns="http://www.example.com/drone/service">
            <droneId>d1</droneId>
        </GetDroneInfoRequest>
    </soap:Body>
</soap:Envelope>
```

**SOAP Response:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
    <soap:Body>
        <GetDroneInfoResponse xmlns="http://www.example.com/drone/service">
            <droneInfo>DJI Mavic — активен</droneInfo>
        </GetDroneInfoResponse>
    </soap:Body>
</soap:Envelope>
```

```xml
<?xml version="1.0" encoding="UTF-8"?>
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">

        <GetDroneInfoRequest xmlns="http://www.example.com/drone/service">
            <droneId>d999</droneId>
        </GetDroneInfoRequest>
    </soap:Body>
</soap:Envelope>
```

```xml

<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">

            <faultstring>Дрон с ID d999 не найден</faultstring>

            </detail>
```

1. **Разделение абстрактного и конкретного WSDL:**
   - Абстрактное WSDL содержит только бизнес-логику (типы, сообщения, порт)
   - Конкретное WSDL добавляет техническую реализацию (SOAP привязка, endpoint)

2. **Документо-ориентированный стиль:**
   - Используется стиль `document/literal`
   - XML документы передаются как есть, без оберток

3. **EJB Stateless Session Bean:**
   - Компонент без состояния
   - Каждый вызов независим
   - Может обрабатывать множество клиентов

4. **Обработка ошибок:**
   - Реализована через SOAP Fault
   - Каждая операция имеет определенные типы ошибок
   - Fault передает детальную информацию об ошибке

5. **Partner Link Type:**
   - Добавлен для возможности использования в BPEL процессах
   - Определяет роль веб-сервиса как партнера

6. **Генерация клиентских классов:**
   - Используется `wsimport` для генерации классов из WSDL
   - Автоматически при сборке проекта через Maven

## Технические детали

### Endpoint веб-сервиса

```
http://localhost:8090/camera2/DroneService
```

**Разбор URL:**
- `http://` - протокол
- `localhost` - хост (или IP адрес)
- `8090` - порт (настроен в `application.properties`)
- `/camera2` - контекстный путь (настроен в `application.properties`)
- `/DroneService` - путь к веб-сервису (настроен в `web.xml` и `JaxWsConfig.java`)

### WSDL URL

**Динамический (от сервиса):**
```
http://localhost:8090/camera2/DroneService?wsdl
```

**Статический (файл):**
```
http://localhost:8090/camera2/ws/droneService.wsdl
```

### Namespace

```
http://www.example.com/drone/service
```

**Используется в:**
- XML-схемах
- WSDL описаниях
- Java аннотациях
- SOAP сообщениях

### Операции веб-сервиса

#### 1. GetDroneInfo

**Назначение:** Получение информации о дроне по его ID.

**Входные параметры:**
- `droneId` (String) - идентификатор дрона

**Возвращаемое значение:**
- `droneInfo` (String) - информация о статусе дрона

**Возможные ошибки:**
- `InvalidDroneIdFault` - неверный или несуществующий ID
- `ServiceUnavailableFault` - сервис недоступен

**Примеры ID:**
- `"d1"` - DJI Mavic (активен)
- `"d2"` - DJI Phantom (неактивен)
- Любой другой - вызовет InvalidDroneIdFault

#### 2. RegisterFine

**Назначение:** Регистрация штрафа для дрона.

**Входные параметры:**
- `droneId` (String) - идентификатор дрона
- `violation` (String) - описание нарушения
- `penalty` (double) - размер штрафа в рублях

**Возвращаемое значение:**
- `result` (String) - сообщение о результате регистрации

**Возможные ошибки:**
- `ValidationFault` - ошибка валидации данных:
  - Пустой `droneId`
  - Пустое `violation`
  - Отрицательный `penalty`
- `ServiceUnavailableFault` - сервис недоступен

#### 3. GetFines

**Назначение:** Получение списка всех штрафов для указанного дрона.

**Входные параметры:**
- `droneId` (String) - идентификатор дрона

**Возвращаемое значение:**
- `fines` (List<String>) - список штрафов в текстовом формате

**Возможные ошибки:**
- `InvalidDroneIdFault` - неверный или пустой ID
- `ServiceUnavailableFault` - сервис недоступен

### Обработка ошибок

#### InvalidDroneIdFault

**Когда возникает:**
- Передан пустой или null `droneId`
- Передан несуществующий `droneId`

**Структура Fault:**
```xml
<InvalidDroneIdFault>
    <message>Текст ошибки</message>
    <droneId>ID, который вызвал ошибку</droneId>
</InvalidDroneIdFault>
```

#### ValidationFault

**Когда возникает:**
- Нарушены правила валидации данных в операции RegisterFine

**Структура Fault:**
```xml
<ValidationFault>
    <message>Текст ошибки</message>
    <field>Имя поля, в котором ошибка</field>
</ValidationFault>
```

#### ServiceUnavailableFault

**Когда возникает:**
- Сервис временно недоступен (в текущей реализации не используется)

**Структура Fault:**
```xml
<ServiceUnavailableFault>
    <message>Текст ошибки</message>
    <errorCode>Код ошибки</errorCode>
</ServiceUnavailableFault>
```
